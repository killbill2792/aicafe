> **AI CAFE local rules:** AGENTS.md always wins. Use the connected GitHub plugin in ChatGPT; read actual repository `AGENTS.md` and `PROGRESS.md` on latest main before code. Do not trust summaries or a previous chat's claim of merge. This skill orchestrates existing `gh-fix-ci`, `gh-address-comments`, `verification-before-completion`, `pr` and `two-axis-code-review` skills; open their SKILL.md only when relevant.

# Own one PR until merged

1. Understand the product before coding: **AI CAFE Supervisor is one proactive, universal café operator**, not a set of hardcoded scenarios. Reuse the existing canonical data, shared financial calculations, single AI loop, authorization, inbox and business services. **Toast is the authoritative POS source**; available supported Toast facts must flow through shared canonical readers and be accessible to the app and Supervisor, without a second reader or invented missing figures. Fetch latest `AGENTS.md`, `PROGRESS.md`, applicable `docs/rules/*` and the approved task brief through the connected GitHub plugin. Load the relevant skills from `docs/rules/skills.md` by opening each applicable `.claude/skills/<name>/SKILL.md`. Verify owner approval for infrastructure and explicit owned/excluded files.
2. Check actual predecessor commits, public exports, changed paths and active PR file overlaps. If independent, start on latest `main`. If dependent on an **open** PR, start from that PR's **branch** and open a **draft stacked PR NOW with base = prerequisite branch**. A dependency not yet merged is **not** a reason to stop opening or coding. Do not edit someone else's owned files.
3. Write the real implementation, smallest changes, no parallel reader/loop/inbox. Add targeted tests proving behavior and failure cases. Use same PR/chat for the entire lifecycle; do not hand off the PR merely because the first iteration is pushed.
4. On every pushed head, inspect real CI, checks and unresolved review threads; fix failures and owner comments in the SAME PR. Do NOT request Codex on each push. Wait for full applicable CI GREEN, current main base, reconciled owner scope and final code/docs. A stacked child remains draft until its parent has merged and the child has rebased to main. Mark ready only then. If ready automatically starts Codex, do NOT also post @codex review. For substantive findings, fix and test together, then request ONE final-head re-review after new green CI. Comments never change HEAD. Avoid doc-only commits after review; a changed head still needs exact-head review. Resolve threads only after executed evidence. No new monitoring or replacement chat. Pending is not clean.
5. Before each merge attempt, verify prerequisites, current main and ownership overlaps. A stacked child can code/test now, but waits for its parent merge/rebase before its one eligible Codex review. Run required CI on the final head and obtain exact-head clean review only after CI is green.
6. Merge only under AGENTS.md with full latest-head CI, clean Codex, resolved findings, executed acceptance, current base and merged prerequisites. Record merge SHA and missing proof in the PR. Coding PRs NEVER edit shared PROGRESS.md; the coordinator updates it separately after merged-main integration proof. No production deployment without owner approval.
7. On actual blocker (secret, owner decision, disallowed scope): keep PR open with precise status and continue independent tasks via dispatcher. Never claim completion because a draft PR exists.

**When to load more:** `gh-fix-ci` for failing CI, `gh-address-comments` and `receiving-code-review` for findings, `supabase` for SQL, `playwright-cli` and `e2e-testing-patterns` for browser behavior, `aicafe-dependency-check` before branching/merge, `aicafe-proof-gate` before marking done.

**Output:** PR URL, branch/base/head SHA, dependency changes since last check, tests actually executed, CI/review state, resolved threads, merge SHA or exact pending blocker.
