# Canonical break-even by period: October 30 owner scope

This is the implementation scope of the accompanying pull request. Follow `AGENTS.md` (one RLS reader per fact, one core money metric, no edits to model text, no POS writes) and `PROGRESS.md`. Other active PRs #318 Events and #319 Menu are out of scope.

## Actual observed defects
1. **Generic misleading estimate reason**: Supervisor `get_break_even` maps *any* estimated input to `profitFeesEstimated`, causing “processing fees include an estimate” even when all observed Toast payment fees are actual. The response asks the owner to “add actual labor and processing-fee records” despite existing actual imported days.
2. **Alternate finance path**: the default no-override chat route reuses `breakEvenSnapshotInputs` from Money/Plan, but ordinary owner overrides cause `unifiedBreakEven` and a different assembled input path. The fallback additionally uses another daily fixed-cost model. Owner-set 20% ingredient cost should not be interpreted as a new hypothetical just because the model passes it.
3. **Unclear period meaning**: a full-month forecast, month-to-date and today's actual/provisional daily break-even are different questions. The current default monthly estimate spreads labor over future days and divides by all open days even for "today". Do not falsely present an average month day as today's recorded staffing cost, or project future labor for month-to-date.
4. **Missing/actual evidence**: historical Toast timecards and payment fees were actual on all 28 covered Oct 2–29 days. Payroll burden is estimated via `businesses.payroll_tax_rate`, not necessarily imported from Toast Payroll. Existing `employee_pay_period_facts` can hold actual employer-tax facts but had zero October pay-period records in SOURCE and TEST during diagnosis. Do not represent saved percentages as imported actuals.
5. **Economic settings differ across cafés**: SOURCE default payroll tax rate 12% (system-estimated), TEST 1.5% (owner-confirmed). The latest mirrored rollups matched but independent recalculation could diverge. Preserve test-owner settings; do not silently overwrite the TEST rate or make a production setting change. Report the mismatch for owner's decision.
6. **Ingredients incomplete**: use complete recipe/product costs when available, otherwise use saved owner 20% ingredient-and-packaging rate. Only ask the owner when neither usable source is present; don't ask again for saved inputs.
7. **Insufficient detail in explanation**: return actual/estimated flags separately for historical wages, employer taxes, future labor, historical Toast fees, projected marginal future fees, fixed bills and saved ingredient assumption. Structured “How I got this” remains deterministic, not invented by a model.

## Required behavior
- Use one canonical daily business-facts reader and **one `lib/metrics/core` break-even calculation** for Money, Plan and Supervisor standard and owner-adjusted scenarios.
- Default “What's my break-even?” = full-month forecast for the currently selected calendar month (labeled projected while incomplete). “So far this month” = month-to-date costs through closed recorded days, plus only appropriate prorated fixed monthly expenses, no future labor. “Today” = today's period only, with recorded/provisional labor if available; don't claim finalized live sales until closeout. Daily average of monthly forecast is distinct from today's target.
- Keep historical Toast wages, timecard zero-wages and actual per-payment fees authoritative. Actual imported employer payroll-tax values outrank saved-rate fallback; if absent, label the saved rate even if owner-confirmed. Show actual-history plus forecast-assumptions separately.
- Missing required fixed/variable inputs produce a qualified known-cost floor or explicit unavailable/partial state, never an unqualified complete amount.
- For identical café, period, as-of, and owner overrides, exact integer-cent parity and consistent provenance across Money, Plan, chat tool and `explain`. Explicitly regression-test actual fees + estimated payroll taxes + saved 20% ingredients, and that changing the owner overrides only the intended input.
- No DB writes, migration, direct Toast connection from AI, production data sync, deploy or merge. All mandated checks and Codex review, resolve P1s. This PR is a cohesive correction of one financial capability; avoid unrelated refactors.
