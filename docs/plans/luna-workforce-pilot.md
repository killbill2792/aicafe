# Luna workforce pilot

The owner approved the first café pilot for AI workforce conversations and scheduled assignments. General chat keeps its existing capabilities during this temporary cutover. All authorized AI employees ultimately use the same runtime, tools, scheduling, business rules and storage.

Employee conversations use the existing private thread keyed by café, owner and employee. Admission uses the saved owner message ID and the existing fixed run plan. The database pins the engine and employee on admission. The browser and minute worker deliver work through the same replacement claim and publish the original saved reply. Rollback changes future admission, retains private history, and drains assignments under their stored engine.

The replacement offers the existing routine draft tool in employee chat. The owner confirms through the existing Save card and API. The API verifies the original owner-authored message, routine and café. A saved objective linked to an employee thread becomes eligible for the replacement on the existing minute tick. General objectives and Watch continue on their current schedule. Both entry points use the same due-admission RPC, lease capacity and occurrence ledger. The database pins the employee and engine once for each occurrence. Rollback holds new workforce occurrences and lets admitted work recover under its existing lease rules.

The replacement model and tool loop is shared by interactive and scheduled work. A scheduled occurrence uses the existing background continuation and usage ledger, rechecks café entitlement and the occurrence lease, and publishes through the existing verified report and owner notice. It carries the original objective and revision without creating a new owner chat message. Only the registered read capabilities are offered during scheduled execution.

## Verification

- A migrated, disposable two-café database verified private employee-thread admission, the general-chat engine pin and same-owner tenant isolation. Rollback kept history and original engine pins, and held new admissions.
- A scheduled workforce assignment entered through the existing routine API and due/claim RPCs. A competing claim was denied. After a simulated interruption immediately after a stored SQL result, a new worker reused the result with the direct database connection removed and published one report on the original thread. The ledger recorded two calls for the same occurrence and no additional owner message. The second café's rows were excluded. These tests use a recorded provider response and real database services.
- The route regressions prove the authenticated minute endpoint selects workforce due work independently of source refresh and the refresh route retains its existing general schedule lane. The current draft still requires protected-entry review, exact-head CI and a fresh browser/model acceptance run.
