# Luna workforce pilot

The owner approved the first café pilot for AI workforce conversations and scheduled assignments. General chat keeps its existing capabilities during this temporary cutover. All authorized AI employees ultimately use the same runtime, tools, scheduling, business rules and storage.

Employee conversations use the existing private thread keyed by café, owner and employee. Admission uses the saved owner message ID and the existing fixed run plan. The database pins the engine and employee on admission. The browser and minute worker deliver work through the same replacement claim and publish the original saved reply. Rollback changes future admission, retains private history, and drains assignments under their stored engine.

Scheduled work starts from the existing routine and its occurrence in the authoritative scheduler. Preserve the café, owner, routine and occurrence IDs, routine revision, due instant, time zone, source instruction and existing destination. Select replacement only for authorized workforce assignments. Share the runtime continuation and tool path with interactive assignments. Keep the existing occurrence and report receipts and revalidate ownership, schedule revisions and tool grants before execution and publication. An occurrence is not an interactive owner message.

Release requires deterministic browser, migrated database, source, crash, steering and rollback proof, followed by an authorized live replacement run with the restricted SQL connection. Enable the first café only after that evidence passes.
