## Production evidence

Vercel `cafe-profit` deployment `dpl_54qZUJnmLyc65BTXNduaT7XYRdVC` serves `747db6df8e788dc3c7244d14122ca8c164c3b41f`. On November 28, 2026, the runtime recorded `unreadable` at 07:48:40, 07:49:03, and 08:02:22 UTC (16,282, 16,340, and 17,676 ms) and `timeout` at 08:03:15 UTC (20,002 ms). The last turn took 106,849 ms across six model calls and five tool calls. Its completion flag records loop termination and the owner reported no useful answer.

The deployed chat uses `runResearchTurn` → `search_web` → `ownerPublicWebSearch` → `searchWeb`. The older `web_search` wording filter is outside that chat path. The shared request uses `web_search` with the production `gpt-6-luna` model, `store: false`, 1,200 output tokens and an independent 20-second timeout. Its parser treats any non-completed status or absent visible output as `unreadable` and truncates successful answers to 1,500 characters and five source links.

OpenAI counts reasoning and visible text against the same output cap. A budget-exhausted response can therefore be `incomplete` with no visible text. Offline fixtures reproduced this application failure mode. The owner waived paid replay of the old implementation. Existing production logs contain neither provider status nor incomplete reason, and the request did not retain a response for retrieval. ## Proposed repair

- Use one public-only research service for the current Supervisor and replacement Luna assignments. Keep the configured OpenAI model and native `web_search`. The service receives the public research objective and relevant public location. Tenant identity, prior private conversation, private tool results, attachments and secrets stay behind the connector boundary. The native model selects, opens and refines sources itself. Use the same owner and café grant for every dispatch and recheck its revision before accepting evidence, restoring a run or publishing a result.
- Read Responses `status`, `incomplete_details.reason`, `error.code`, `output` and `usage`. Use completed search actions and `url_citation` annotations to distinguish grounded evidence from absence of evidence. Keep complete answer text and clickable citations with safe HTTP(S) URLs. Expose partial or failed results accurately, including provider limits and permission loss. Record sanitized status, reasoning and output token counts, action counts, duration and provider request ID on the existing usage and diagnostic paths. Keep provider payloads and query text out of application logs.
- Use the existing run and tool-call identity for continuation and usage. The current durable owner run and Luna assignment fences own the accepted answer, sources, source permission revision and retry state. Use the existing budget reservation and settlement for the model and hosted tool calls. Prefer stateless requests and the physical worker deadline for short work. If live evidence requires work across slices, evaluate the provider's background response ID for the public-only operation and review its storage implications before adopting it. Existing run state remains the authority for publication and resume. ## Verification and repository gates

- Verify the corrected implementation on the original question and unrelated quick, comparative and multi-source research. Inspect provider status, usage, actions, annotations and timing, and record sanitized receipts. The logged incident lacks the provider body, so a fresh replay cannot establish the exact historical response.
- Exercise timeout and recovery, partial or empty responses, citations rendered as clickable links, cancelled work, owner revocation during execution and across resume, two cafés and a confidential-value canary. Verify usage settlement, persisted answer and permission provenance. Use disposable data for paid acceptance and the existing production deployment checks for an authorized release.
- The Luna boundary guard protects `lib/ai/agent/webSearch.server.ts` and the legacy entry and turn. Before those files can change on the implementation PR, protected main must contain independently reviewed entries for the exact source and regression blobs. [The existing exception precedent](https://github.com/killbill2792/aicafe/pull/596) shows how the repository landed these approvals separately. The proposed implementation stays on one PR and requires owner direction on the prerequisite.
- Paid reproduction and verification require a separate owner grant for a trusted bounded run. The shared Luna runner's current broker rejects hosted `web_search`, and the replacement assignment provider explicitly rejects that runner's paid mode. A trusted route must be authorized for hosted search proof before a provider call. Preserve the existing CI, Codex review and production approval rules.
