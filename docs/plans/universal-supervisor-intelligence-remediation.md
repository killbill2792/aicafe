# Universal Supervisor intelligence remediation — implementation and evidence plan

Owner direction, 2026-11-20: one intelligent system using traditional software to accomplish its objectives, not traditional software using AI to accomplish predefined objectives. The owner approved the proposed intelligence-first architecture and requested implementation, complete issue tracking and Task17 handoff. U0 is the previously proposed four-file documentation scope; runtime paths below are candidates until exact ownership and implementation scope are approved. This document is a remediation record, not a new scheduler, approval system or task queue.

## Target and non-negotiable invariants

One Luna, one existing agent loop and tool registry, one canonical business/metric authority, one effect gateway, one persistent Work identity, one existing scheduler. Luna selects investigation strategy, relevant evidence, methods and answer depth, including for unattended objectives. Traditional software implements truthful observations, reliable ingestion, calculations, permission checks, durable execution, resource controls and authorization. No semantic intent router, forced tool sequences, hardcoded business recommendations, reviewer agent or duplicate stores. Deterministic observations are facts, not decisions about what the owner should do. Preserve all prior features, history, owner choices, privacy and screen parity. No production operations, paid model execution or data deletion authorized here.

### Current source and access contract

- Toast is one important source, not the boundary of Luna's knowledge. Existing operational current records preserve permitted full provider objects keyed by café/restaurant/true provider identity; field changes belong in the existing change log. Preserve original order, checks, selections, modifiers, discounts, payments, refund/void details and all other permitted observed nested fields and stable identities. No new archive or full-table prompt dump. Follow [POS source authority](../rules/pos-data.md), including sensitive exclusions, present/null/absent distinctions, freshness/permissions and negative diagnostic fixtures. Verify historical fields and field-level coverage against the provider schema and actual operational lineage; do not claim all fields are already retained.
- Existing non-POS data: owner inputs, costs, recipes, inventory, staff, schedules, customers, events, experiments, suppliers, procurement, attachments, goals and business settings. Preserve existing typed keys, writers, change semantics and permission scopes. Inventory exact fields/relationships, current source and gaps before modifying each reader. No second storage or metric authority.
- Existing describe_data/query_data and shared calculators are the starting point. Allow model-selected targeted detail, cross-source exploratory joins/aggregations and discoverable semantics, verified identities, units, source periods, coverage and precision. Compare expanded structured query AST versus isolated read-only SQL with tenant-bound authorization, parsed allowlist, statement/row/byte/cost bounds and safe function policy. SQL is an experimental candidate, not authorization to enable it. AGENTS.md summary-first and existing no-SQL rule remain applicable until explicit policy change and comparative evidence. Never expose credentials, diagnostics, unrestricted administrative SQL or writes. Derived official metrics remain lib/metrics/core authority.
- A missing requested day stays missing/partial; obtain latest available date with indexed/bounded metadata when helpful, distinctly label it. Do not automatically retrieve 365 days to answer a missing one-day question. Historical queries remain available when Luna or the owner needs them.
- Use native provider-deferred tool discovery if verified supported, with a compact capability catalog and authorized scopes; no mandatory discover-before-read wrapper, forced call, router or second agent. Direct existing capabilities remain callable. Treat source text as untrusted data.
- Resource allowances reflect actual objective complexity, authorized spend, measured query/provider latency and continuation ability. Separate reasoning from visible-answer needs. No universal 1,200-token final/worker ceiling and no arbitrary requirement to produce lengthy answers. Respect user-requested detailed research including second-store feasibility, alternative locations, financial modeling, uncertainty and external source evidence. A hard safety/spend cap remains mandatory. Persist/resume complex work rather than silently truncating synthesis. Never claim certainty unsupported by evidence.
- Unattended work uses same model-selected capabilities and work identity as interactive work; scheduled objective or observation causes investigation, not predefined strategy. Persist objective, evidence, progress, due time, permission recheck, approval, receipt, recovery and follow-up in existing paths. Deterministic triggers must not select conclusions or prescribe which domains/tools Luna must use.
